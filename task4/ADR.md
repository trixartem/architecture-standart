### Решение

#### Концептуальная архитектура:

- Сервис «Депозиты» расширяется:
  - предоставляет API для системы кол-центра;
  - периодически генерирует CSV-файл с актуальными ставками;
  - файл передаётся через ручной процесс сотрудником банка партнёру (например, email).

- Система кол-центра выполняет GET-запрос к API и получает список ставок.


#### Диаграммы

- [context.puml](context.puml)
- [components.puml](components.puml)


### Альтернативы

1. Передача ставок вручную в Excel из АБС
   - Ручная работа, риск ошибок, высокая нагрузка
2. Расширение системы кол-центра для расчёта ставок
   - Дублирование логики, нарушение целостности
3. Подключение партнёра через API
   - Партнёрская система не поддерживает это

**Недостатки, ограничения, риски**

- Нельзя организововать непреревное обновление ставок для партнеров
- Необходимо ограничить доступ к API и контролировать версию файла

### Крупные задачи

**Сервис «Депозиты»:**
- Реализация REST API для ставок
- Планировщик генерации CSV-файлов
- Реализация экспортного формата
- Логирование и аудит выгрузки

**Система кол-центра:**
-  Интеграция с REST API
-  Обновление интерфейса: вкладка ставок

**Партнёрский кол-центр:**
-  Регламент на получение и загрузку CSV-файлов
-  Инструкции по использованию Excel
